
# User Response Design Process

## Overview

The collection of design documents represents the systematic development of the **User Response Model** for Environment V2. Rather than directly mapping environment variables to observable user reactions, the design adopts a **latent-variable modeling approach**, where an unobservable psychological appraisal is first computed and then transformed into an observable user response.

The overall design follows a research-first methodology:

1. Define the conceptual meaning of user response.
2. Identify its causal determinants.
3. Design a latent appraisal construct.
4. Derive the mathematical formulation.
5. Map the latent appraisal into observable response categories.
6. Integrate all components into the final simulator.

# Workflow A — Latent Appraisal Model

This branch addresses the question:

> **How should the user's internal evaluation of a persuasive interaction be represented?**

Rather than modeling observable responses directly, the simulator first estimates an unobservable **latent appraisal**, which summarizes the user's overall evaluation of the interaction.

---

## Stage 1 — Conceptual Definition

### `concept.md`

The design process begins by defining the meaning of **user response**.

The document establishes that user response is:

* an immediate behavioral reaction,
* observable,
* transient,
* distinct from persistent state variables such as fatigue, adherence, trust, or personality.

This separates immediate interaction outcomes from long-term user characteristics.

---

## Stage 2 — Latent Psychological Construct

### `latent_appraisal_construct.md`

Rather than generating user responses directly, the design introduces the concept of **latent appraisal**.

The proposed causal process becomes

```text
Persuasive Intervention
        │
        ▼
Latent Appraisal
        │
        ▼
Observable Response
```

This document establishes latent appraisal as the central psychological construct underlying the response model.

---

## Stage 3 — Causal Analysis

### `04_causal_analysis.md`

Once the latent construct is defined, the next step is determining which variables should influence it.

Candidate causal variables are evaluated to identify the minimal set of parent nodes.

The selected inputs become

```text
Task Success (Y)

Fatigue (F)

Excess Intervention (X)

Repetition (k)
```

These variables define the causal structure of the latent appraisal model.

---

## Stage 4 — Design Requirements

### `05_requirements.md`

Before proposing equations, formal design requirements are established.

The appraisal function is required to satisfy

```text
Mathematical Requirements
Behavioral Requirements
RL Requirements
```

including continuity, monotonicity, behavioral plausibility, interpretability, and suitability for reinforcement learning.

---

## Stage 5 — Candidate Mathematical Models

### `06_candidates.md`

Multiple mathematical families are explored for representing latent appraisal.

Candidate approaches include

```text
Additive Linear

Benefit–Cost

Non-linear Interaction Models
```

Rather than immediately selecting a formula, alternative model families are compared conceptually.

---

## Stage 6 — Benefit–Cost Decomposition

### `07_benefit_cost.md`

The preferred formulation is refined by decomposing latent appraisal into

```text
Benefit

+

Cost
```

where

* Benefit is primarily driven by successful task completion.
* Cost is generated by fatigue, excessive intervention, and repetition.

This decomposition provides an interpretable psychological structure for the appraisal function.

---

## Stage 7 — Semantic Validation

### `08_appraisal_semantics_audit.md`

Before finalizing the formulation, the semantic meaning of latent appraisal is validated.

The document confirms the temporal ordering

```text
Robot Action

↓

Latent Appraisal

↓

Observable Response

↓

Task Completion Effects
```

and verifies that the appraisal construct has a consistent psychological interpretation.

---

## Stage 8 — Action-to-Appraisal Analysis

### `09_appraisal_action.md`

This stage evaluates whether persuasion actions require an explicit positive interaction-quality variable or whether the selected action itself sufficiently explains positive appraisal.

The analysis concludes that explicit action characteristics can adequately influence latent appraisal without introducing additional psychological constructs.

---

## Stage 9 — Final Appraisal Model

### `user_response_appraisal_model_v1.md`

The previous conceptual work culminates in the final latent appraisal equation

[
z
=

b
+
w_YY
----

## w_FF

## w_XX

w_k\hat{k},
]

where

* (Y) represents task success,
* (F) represents fatigue,
* (X) represents excess intervention,
* (\hat{k}) represents normalized repetition.

This document defines the mathematical specification of the latent appraisal model.

# Workflow B — Response Mapping Model

The second branch addresses a different question:

> **How should the latent appraisal be converted into an observable user response?**

---

## Stage 1 — Mapping Alternatives

### `mapping.md`

This document evaluates candidate mapping strategies.

Candidate approaches include

```text
Deterministic Thresholds

Probabilistic Mapping

Ordinal Logistic Models
```

The objective is to preserve both stochasticity and ordinal relationships between response categories.

---

## Stage 2 — Final Mapping Architecture

### `user_response_mapping_model.md`

The selected architecture consists of three stages

```text
Environment State

↓

Latent Appraisal Score

↓

Ordinal Logistic Mapping

↓

Response Probability Distribution

↓

Sample User Response
```

The response space is

[
R_t
\in
{
VP,,
P,,
I,,
N,,
VN
}.
]

The document freezes the mapping architecture while allowing future calibration of probability parameters.

## 2. Response Mapping Model

**Document:** `user_response_mapping_model.md`

This document specifies how the continuous latent appraisal score is transformed into an observable user response using an **ordinal logistic mapping**.

Rather than producing deterministic responses, the mapping generates a probability distribution over the ordered response categories before sampling the final response.
